# REITs发改委申报材料 · 图片生成

## 共享项目信息

写作前先读取 `../planning.md`（`skills/` 目录下所有 skill 共用的总纲），项目名称、路径等信息统一从这里取。

## 本skill负责的范围

申报材料里所有需要画的示意图，常见的有：

- **第二章"（一）法律关系"**：股权结构图，从项目公司/原始权益人一路穿透到最上方的自然人股东，标注每一层持股比例，底部标注项目公司持有子项目。
- **第二章/第三章"产品架构"**：基金-专项计划-项目公司-底层资产这类结构链条图。
- **第三章"实施步骤"**：如果本项目的交易步骤复杂（比如涉及股权转让、增资、减资等多步资产重组），且写成纯文字不容易看清先后关系和层级，画一张步骤流程图。
- **第七章"资金流向图"**：募集资金从基金流向项目公司/发起人等各方的路径图。

本skill不负责判断"这里要不要配图""图里的持股比例/交易步骤对不对"这类业务判断——那是各章节reading skill的工作。各章节skill如果判断某处需要插图，就把"有哪些方框、谁连向谁、连线上标什么字"这些信息交给本skill，由本skill统一画图、统一管理插入位置，避免每个章节各写一套画图逻辑。

## 关系数据存放在 `relations.xlsx`

本skill目录下自带一份 `relations.xlsx`，**用户直接在Excel里编辑，本skill每次运行都读取这一份文件**，不需要用户单独发JSON或临时文件给你。表结构约定（以现有的 `REITs设立方案` sheet为范例）：

- **一个工作表（sheet）对应一个申报材料章节**，sheet名建议用章节名（比如"REITs设立方案"对应第三章）。
- 一个章节经常不止一张图，用**"图片标题"**这一列分组：这一格非空的行是一张新图的开始，紧接着"图片标题"留空的行都属于同一张图，直到下一个非空的"图片标题"。
- 列含义：`上级`/`下级`（必填，两个方框）、`标注`（箭头旁的文字）、`平级`（填"是"表示这一行是横向平级关系，不是上下级）、`线型`（"虚线"/留空=实线）、`颜色`（"红色"等，留空=黑色）、`二级标题`/`三级标题`/`四级标题`（这张图挂在模板哪个标题层级下面，只在"图片标题"那一行填一次）、`图片标题`（图注文字，同时也是输出文件名）。完整字段说明见 `scripts/draw_diagram.py` 头部docstring。
- `二级/三级/四级标题` 只是给人看、帮助定位的章节路径，**不等于**装文档时用的 `anchor_text`——`anchor_text` 必须是模板里一字不差的原文，还需要按下方"输出格式"那一步对照 `scripts/read_chapter.py` 的输出来确定。

新增一张图：如果和已有图属于同一章节，在对应sheet里新起一个"图片标题"分组；如果是新章节，新建一个sheet（sheet名=章节名）。不确定某张图该归在哪个章节/哪个标题层级时，跟用户确认清楚再写进Excel，不要自己猜。

## 工作流程

1. **收集这一轮要画的图**：可以是某个章节skill在写作过程中主动过来说"这里需要一张XX图，节点和连线是……"，也可以是用户直接告诉你"帮我画一下资金流向图"。不管来源是谁，最终都要落到"在 `relations.xlsx` 对应章节的sheet里新增/修改一个图片标题分组"这一步——本skill自己不维护另一份数据源。

2. **人机来回确认每张图**：
   a. 和调用方（用户或章节skill）确认清楚"这张图属于哪个章节、挂在哪个标题层级下面、图注叫什么、有哪些方框、谁指向谁、连线上标什么字、要不要虚线/红色/平级关系"，把这些内容写（或改）进 `relations.xlsx` 对应sheet的对应分组里。
   b. 运行 `python scripts/draw_diagram.py relations.xlsx <输出目录>`，一次性把工作簿里所有sheet、所有分组都渲染成图（文件名取自"图片标题"），脚本会把每张图对应的"章节路径"打印出来。用 Read 工具把这一轮涉及的PNG展示给用户看。
   c. 用户要调整（加/删节点、改标签文字、调整线型颜色、调换左右顺序）就改 `relations.xlsx` 里对应的行，重复b直到用户确认满意——只会重新影响改动所在的那个分组，不影响同sheet里的其他图。
   d. 记录这张图定稿后的文件路径（脚本已经打印过），以及 `relations.xlsx` 里记的"二级/三级/四级标题"。

3. **确定真正的 `anchor_text` 并按章节归类输出**：对照 `scripts/read_chapter.py` 读出来的模板真实结构，把每张图的"二级/三级/四级标题"翻译成模板里下一个标题的原文（图片插入在这个 `anchor_text` 之前）。每个涉及插图的章节各出一份 `chN_diagrams.json`（比如 `ch3_diagrams.json`），结构和其他章节JSON一致（`chapter_heading` + `items`），`items` 里全部是 `anchor_type: "image"` 类型，见下方"输出格式"。同时给用户一份人类可读的清单（图名 / 文件路径 / 所属章节 / 确定的插入位置），让用户最后确认或调整——**插入位置以用户这一步的确认为准**，不要自作主张。

4. 用户确认后，这些 `chN_diagrams.json` 和对应章节自己产出的 `chN.json` 一起交给 `reits-writing` 装配，装配脚本原生支持 `image` 类型，不需要额外改动，两份JSON按同一章节紧挨着传入即可（顺序建议：`ch2.json ch2_diagrams.json ch3.json ch3_diagrams.json ...`）。

## 输出格式

`chN_diagrams.json` 示例（对应第二章的股权结构图）：

```json
{
  "chapter_heading": "二、参与主体情况",
  "items": [
    {
      "anchor_type": "image",
      "anchor_text": "（二）项目公司情况",
      "image_path": "equity_chart.png",
      "width_inches": 6.0,
      "caption": "图1  现状下的项目主要法律关系图"
    }
  ]
}
```

- `anchor_text` 必须是模板里原样存在的标题/表格标题文字，图片会插入在它之前——这一点和其他章节JSON的 `heading`/`table_caption` 锚点用法完全一致。
- `width_inches` 可选，不填则按图片原始尺寸插入，图偏大时建议显式设置一个合理宽度（一般6~6.5英寸比较适合A4页面）。
- `caption` 可选，图片下方居中的图注文字（比如"图1  现状下的项目主要法律关系图"）。同一节里如果要插多张图，图注编号（图1、图2……）由调用方（章节skill）按顺序给出，本skill不做全局自动编号。

配套的清单（讲给用户看，不是JSON的一部分）：

| 图名 | 文件 | 所属章节 | 建议插入位置 |
| --- | --- | --- | --- |
| 股权结构图 | equity_chart.png | 二、参与主体情况 | （二）项目公司情况 之前 |
| 资金流向图 | fund_flow.png | 七、募集资金用途情况 | （二）资金流向图 之前 |

## 画图脚本使用说明

具体的表头格式、层级怎么自动推算，见 `scripts/draw_diagram.py` 头部的docstring，不在这里重复。这个脚本是通用的"方框+箭头"层级图渲染器，不专属于股权结构图，产品架构图、资金流向图、步骤链条图都能用同一个脚本画。脚本也保留了单张图的JSON输入模式（`python draw_diagram.py <edges.json> <输出png>`），一般用不上，`relations.xlsx` 才是主要工作方式。

如果某张图确实不是"层级方框图"能表达的形状（比如需要画地图、平面图、非层级的网状关系），先跟用户确认清楚要用什么形式呈现，不要硬套这个脚本画出不合适的图。
