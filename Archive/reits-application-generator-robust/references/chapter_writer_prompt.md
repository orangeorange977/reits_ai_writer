# 子agent提示词模板：按章撰写（第二步 phase 3~5）

主agent用法：对需撰写的每一章，复制下面「提示词正文」，替换 `{{...}}` 变量后作为一个 Task 发出。
**发前必做：逐章跑 `python {SKILL_DIR}/scripts/read_chapter.py "<填充基底.docx>" "<本章标题>" "<下一章标题>" > {WORK_DIR}/ch{N}_structure.txt`，核对首行「实际命中」与段数量级后再委派**（章界失效在主agent手里发现，不烧子agent的时间；子agent不自己跑脚本）。
**尽量并行：同一条回复里一次性发出全部章节任务（常规 5 个：ch1 / ch2 / ch4 / ch5 / ch6），不要分批、不要逐个串行发；一章一 Task，重跑亦然。**
> 第三章（REITs设立方案）与第七章（募集资金用途情况）**由业务人工维护，不委派**——它们是业务决策而非材料提取所得。

变量：
- `{{N}}`：章号，**只取 `1` / `2` / `4` / `5` / `6` 五个值**（三、七章人工维护，不委派——不要用本模板发第三、七章任务）
- `{{CHAPTER_NUM_CN}}`：章号中文序号（`一`/`二`/`四`/`五`/`六`），用于 fill_plan 顶层 `chapter` 字段
- `{{CHAPTER_TITLE}}`：章标题（如「四、项目基本条件」）
- `{{SKILL_DIR}}` / `{{WORK_DIR}}`：绝对路径

**每章的特殊要求都在各自的 guide 里**，不再堆在本文件——`templates/chapter_guides/ch{N}_guide.md`（手工维护，切片脚本不覆盖）。发任务时只让子agent读该章的 guide，跑到哪章加载哪章，互不干扰。

各章 guide 覆盖的要点：

| 章 | guide 里写了什么 |
|---|---|
| ch1 | 表格已填则不动只补正文；表1 字段映射与 4 个复合行拼接口径；四类特殊限定判定；可扩募资产分支 |
| ch2 | 表格与违法违规/信用/执业资格/中介机构固定句式段已由脚本生成，只写创作段（法律关系/业务论述/财务分析）；取数只读 ch2_data.json 切片；多主体成倍展开；工商/信用信息字段用法（`tyc_report.*` 隔离命名空间）；财务三表逐科目取数口径与读法 |
| ch4 | **锚点契约（条目数 ≤28 = 19 指导文字锚点 + 9 标题/注改写）**；（四）（五）共 5 个 H3 须用 `styles` 新建；15 表清单与 3 张模版表的表头/行标签改写；**跨章防火墙（禁写第五章手续内容）**；同名指标取值优先级 —— 本章锚点缺口最大、最易「小节标题被正文顶替」 |
| ch5 | **锚点纪律（条目数 ≤31）**、标题层级与 `styles` 用法、6 类土地情形、来源标注分类 —— 本章最易错位 |
| ch6 | 模版只 1 段需自建 4 小节 30+ 段；两份范例的要点并集与费用层级差异 |

**为什么你做了也一定是错的**（不是流程洁癖，是技术上不可能做对）：

1. **你不知道该从哪个基底写起**。全文档有固定应用顺序 `phase1 → phase2表格 → phase5表格 → ch1 → ch2 → ch4 → phase4表格 → ch5 → ch6 → 附件清理 → 表号重排`，当前排到哪一步、HEAD 基底是哪个文件，**只有主agent知道**。你从任意基底独立写出的 docx 与其它章的写入**互相排斥**，无法合并，只能丢弃。

### 来源标注（硬要求，与篇幅同等重要）

本项目要求**最终文档里所有AI填充的实质内容都在正文标明来源**。所以你写的**每个 `paragraphs` 条目都要带 `citations` 数组**，脚本会按 `citation_rules.json` 的话术渲染成括注写进正文。

四类来源，按内容性质选（`type` 字段）：

| type | 用在什么内容 | 必填字段 | 渲染结果示例 |
|---|---|---|---|
| `material` | 来自证明材料的数据、事实、文件引用（**绝大多数**） | `attachment_no` | `（提取自附件25-1《资产评估报告》第43页）` |
| `knowledge` | 政策法规原文、产业目录条目、行业公开资料（取自 `industry_knowledge.json`） | `name` | `（参考自国家发展改革委《产业结构调整指导目录（2024年本）》第一类鼓励类第四十六条）` |
| `computed` | 由公式算出的数（资产负债率/评估净值/净回收资金；**EBITDA 除外：不计算，直接写【待填写】**） | `formula` | `（据2024年审计报告数据按“资产负债率=总负债/总资产×100”计算）` |
| `pending` | **取不到来源时的唯一合法写法** | 无（建议给 `field`，只写入todo） | `【待填写】` |

写法（`anchor` 指定括注插在正文哪个子串之后；省略 `anchor` 则插到段末句号之前）：

```json
{"match": "说明项目评估情况",
 "replace": "本项目评估值为757,700.00万元，评估基准日为2024年6月30日。",
 "citations": [
   {"type": "material", "attachment_no": "25-1", "doc_name": "资产评估报告",
    "page": 43, "anchor": "757,700.00万元"}
 ]}
```

**六条铁律**：

1. **`attachment_no` / `page` 只能来自 `extracted_data.json` 的 `_attachment_no`/`_page`（或记录自带的 `attachment_no` 字段），或 `base_vars.json` 的 `citations` 段。取不到就写 `{"type":"pending","field":"<字段路径>"}`——严禁凭印象编号、严禁"猜一个看起来合理的"。** 交付前的 `validate_output.py` 会拿 `proofs_index.json` 逐个核对正文里的附件编号，编造的会被判 FAIL 打回。
2. `attachment_no` 只写编号本身（`13-1-5-1`、`25-1`），**不要带「附件」二字**；`page` 只写数字或区间（`43` / `43-45`），不要写「第43页」。**没有页码的材料（docx/xlsx，如天眼查专业版企业信用报告）不要编页码**——改写 `section`（报告内小节名，如 `"2.1工商信息"`），两者互斥、取不到就都不写。
3. **`anchor` 必须是你自己 `replace` 文本里真实存在的子串**（预检会校验）；不确定就别写 anchor，让括注落到段末。
4. **不要用括注凑字数**：校验器统计章节字数时会先把括注全部剔除，注水无效。
5. **同一段内同一份材料只标一次**（第二次起省略或用短式）；下列内容**免标**：小节标题、纯衔接/总结句、「不涉及。」这类短句、40字以下的短段。
6. **不要自己写括注文字**（如手动在 replace 里打「（来源：xxx）」）；统一用 `citations` 字段，由脚本渲染，保证全文话术一致。若你确实已在 replace 中写了标准话术，脚本检测到重复不会二次追加。


### 撰写要求

1. **篇幅和结构对标范例**：范例本章有多少段、分几个小节、每节多深，你就写到同一量级。**严禁只写几句话应付**——历史事故：第六章只写了 83 字，而范例是 3700 字。
2. **`ch{{N}}_structure.txt` 里的每一段指导文字都要有对应的替换条目**，不得只挑几段写。结构切片里本章有多少段指导文字，`paragraphs` 就应有相应数量的条目。（前提是切片未越界——见上方第 1 项的段数自检，量级异常时停手上报而不是照单全收。）
3. **数据只能来自 extracted_data.json / base_vars.json**：
   - 范例里的**任何数字、日期、机构名、项目名都不得照抄**（那是别的项目的数据，抄进来就是重大事实错误）
   - 范例中的 `【原始权益人全称】` 这类占位符，对应换成 base_vars.json 里本项目的实体名
   - 数据取不到就写 `【待填写】`，具体缺失字段写入todo，**绝不编造、不用示例值兜底**
   - **每处引用都要能说出出处**：写这句话时同步在本条目的 `citations` 里登记来源（见上方「来源标注」）
4. **金额格式**：万元、保留2位小数、千分位逗号（如 `757,700.00`）。审计报告里以「元」为单位的数值必须除以 10000 换算。
5. 引用附件用「附件{编号}-{序号}」实际编号，不要留 `{附件编号}`。编号必须真实存在于 `extracted_data.json`（交付前会被 `proofs_index.json` 逐个核对）。

6. 需要插图的位置（法律关系图、架构图、资金流向图等）不要自己画，用 `insert_image_placeholders` 插占位框，占位文字写明图应包含的内容。

### 输出

产出**两个文件**：正文走 `{{WORK_DIR}}/fill_plan_ch{{N}}.json`，表格走 `{{WORK_DIR}}/ch{{N}}_tables.md`（见下）。

`fill_plan_ch{{N}}.json` 结构：

```json
{
  "chapter": "{{CHAPTER_NUM_CN}}",
  "paragraphs": [
    {"match": "<从 ch{{N}}_structure.txt 里复制该段原文的前15~25字>",
     "section": "<该段所属小节，如 （三）3；本章模版有小节划分时必填>",
     "replace": "<你撰写的实质内容，多段用 \\n 分隔>",
     "styles": ["<可选：与 \\n 分段一一对应的样式，如 Heading 3；正文分段写 null>"],
     "citations": [{"type": "material", "attachment_no": "13-1-5-1",
                    "doc_name": "企业投资项目备案通知书", "page": 1,
                    "anchor": "<replace 中该数据的准确子串，可省略>"}]}
  ],
  "tables": [],
  "insert_tables": [],
  "insert_image_placeholders": [],
  "replace_ranges": []
}
```

⛔ **`tables` 一律保持空数组——本章要填的表格不写在这个文件里，也绝对不要写 `table_index` / `row` / `col`**。

**表格另出一个文件** `{{WORK_DIR}}/ch{{N}}_tables.md`，只写「表号行 + Markdown 表」，由主agent跑 `md_table_to_fill_plan.py` 转换（ch1 走 cells 出口实测坐标；ch2 及以后章节走 `--emit rebuild` 直接产 `rebuild_tables`，无坐标依赖）：

```
表#  项目概况

| 字段 | 填写内容 |
| --- | --- |
| 项目名称 | 南方某某数据中心REIT |
| ...
```

- **表号统一写 `表#`**（井号，不要自己编数字；编号交付前由主agent跑 renumber_tables.py 全篇统一重排）；标题写表格上方的实际标题
- **正文引用表格一律写「下表」「如下表所示」**，⛔ 禁止在正文里硬编码「表5」「表4-4」这类表号——表号重排后必然指错，校验会打 WARN
- 字段名/表头**逐字照抄本章 guide 给的表**（guide 写的是官方模版原文；实际基底若被业务改过，脚本会用模糊回退匹配并报 WARN，属正常）
- 2 列表按「字段名→值」写；≥3 列表按表头顺序逐行写，最后一行是「合计」时照写「合计」
- 「项目总体情况」「子项目1」「合计」这类**分节标题行 value 一律留空**
- **已由业务填好、不需要改的表，不要出现在这个文件里**
- 本章没有需要填的表格时，**不产出该文件**

⚠️ **你在正文里写的每个表标题段（「表#  …」）与「图 X-Y …」标题段，都必须真的会有一张表/图占位框跟在它后面**：模版缺失的表由主agent的脚本**以你写的这个标题段作锚点新建/重建**（`rebuild_tables` 的 `create_after`，第四章 12 张新表全是这样），图则靠你自己写 `insert_image_placeholders`。因此——
- **表标题文字必须与本章 guide 给的清单逐字一致**（差一个空格，那张表就插不进文档）；
- **不确定会不会有这张表时，不要凭空写标题段**；数据缺失的表，正文改写「相关数据待补充」而不是「下表列示…」这类肯定句。
- 交付校验有 `表标题配对` 检查（标题段后没有表格实体一律 FAIL）与 `表格实体[四]≥12`。实测事故：第四章正文写了 15 个表标题，文档里只有 3 张表有表格实体，另外 12 张只有标题文字。

`replace_ranges`（范围替换：`{"start_match": "...", "end_match": "...", "replace": "...", "delete_tables": false}`）**仅用于本章出现大段连续的模版框架文字、且整段都不适用需要合并替换时**；正常的指导文字改写一律用 `paragraphs` 逐段替换，多数章节此字段保持空数组。**不要用它删除跨章节范围**，end_match 必须落在本章内部。（它同样支持 `citations` 字段。）

**`match` 必须是基底原文的准确子串**（匹配规则是子串包含，逐字一致才命中）——直接从上面第 1 项 `ch{{N}}_structure.txt` 里复制，不要凭记忆写、不要改标点。

⚠️ **`match` 必须在全文档唯一**：若同一子串在模版里出现多处（如第五章的 `1.总体情况` 出现两次），预检会按 ERROR 拦截，必须加长 match 到能唯一区分，或显式写 `occurrence` 指定第几处。**不要靠"反正会命中第一个"蒙过去**——那正是内容写进错误小节的成因。

⚠️ **`chapter` 与 `section` 是防错位的定位闸门，务必填写**：
- 顶层 `chapter` 写本章中文序号（`"一"`/`"二"`/`"四"`/`"五"`/`"六"` 之一，即 `{{CHAPTER_NUM_CN}}`），预检会校验**每个条目命中的段落都落在本章范围内**，跨章误命中直接报 ERROR。
- 条目级 `section` 写该段所属小节标题的前缀（如 `"（三）3"`、`"（一）"`），预检会进一步校验命中位置落在该小节区间内。本章模版有 `（一）（二）…` 小节划分时**必填**。
- 若你所在章节的 `manifest.json` 条目提供了 `anchor_map`（目前 ch5 有），**`match` 只能逐字取自其中，`section` 取对应的键**。

⚠️ **一段模版只允许一个条目**：每个 `paragraphs` 条目的 `match` 必须指向模版中**不同的段落**。第一条替换后该段原文即消失，指向同一段的后续条目会全部定位失败（预检也会按 ERROR 拦截）。一段指导文字需要多点展开时，把全部内容写进同一个 `replace`（用 `\n` 分段，fill_docx.py 会把 `\n` 拆成独立段落并继承原段格式），**不要对同一段模版创建多个条目**。同一条目里可以放**多条 citations**，分别用 `anchor` 定位到不同的数据点。

⚠️ **条目数不等于产出段数**：篇幅门槛按最终文档段数算（`\n` 拆分后），条目数只受模版可替换段数约束。**条目数超过模版可替换段数就是错的信号**——说明你在编造 match。正确形态是"少量条目 × 每个 replace 内多段"。

⚠️ **段落样式（`style` / `styles` / `auto_heading`）——防"正文变成大号加粗标题"与"层级塌平"**：段落替换**保留原段落的 Word 样式**，`\n` 拆出的每个新段落也继承同一样式。四条规则：
- **锚点必须是指导文字段落，不能是小节标题**。**例外**：本章 guide 明确声明「模版无指导文字锚点」时（目前仅 ch1），允许 `match`=小节标题，但 `replace` 首段必须是标题原文本身、且 `styles` 对应位声明标题样式（完整写法见该章 guide）。若 match 命中的是标题样式段落而你没声明样式，替换出的正文会全部带标题样式（Word 里大号加粗、层级分不清，还污染导航窗格与自动目录）。预检会按 ERROR 拦截。
- **模版里没有的小标题需要你新建**：把小标题作为 `replace` 的一个 `\n` 分段，并在 `styles` 数组对应位置写 `"Heading 3"`（其余分段写 `null`）。
- **`（一）xxx` 这类小节标题不用管样式**：`auto_heading` 默认 `"h2"` 会自动把它们升为 Heading 2（第六章 4 个小节标题全靠它）。⛔ **不要写 `auto_heading: "off"`**，否则小节标题落成正文，导航窗格里本章下面一个子节都没有（第三步按样式硬查会 FAIL）。
- **只改标题文字、保持标题样式**时用 `style`（字符串），它对本条所有分段生效。
- 兜底行为：首段是标题样式时，`\n` 拆出的后续段落会被自动降为正文，不会出现"20 段全是标题"。

⚠️ **字段名只有 `match` / `replace` / `citations` / `section` / `style` / `styles` / `auto_heading`**（可选 `occurrence`），不要写成 `text`、`replacement`、`source`、`reference` 等——错误字段名会被预检按 ERROR 拦截。
