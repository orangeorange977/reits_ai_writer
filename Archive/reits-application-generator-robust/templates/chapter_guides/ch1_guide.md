# 第一章「项目基本情况」写作指南

> 手工维护，脚本不覆盖。配套 `chapter_examples/ch1_example.md`（标准范例）。
> **本章真实结构读 `<work_dir>/ch1_structure.txt`**（主agent委派前已用 read_chapter.py 从实际填充基底现读并核过章界）。⛔ 子agent不自己跑脚本、不读基底 docx。主agent切结构命令：
> ```bash
> python scripts/read_chapter.py "<填充基底.docx>" "一、项目基本情况" "二、参与主体情况" > <work_dir>/ch1_structure.txt
> ```
> 它输出段落原文（取 `match` 用）、每张表的**实际 table_index / 尺寸 / 全部行**，并直接带出已填内容——不必再单独读一遍 docx 判断哪些已填。
> 下文表格里的【字段】= 从 `<work_dir>/ch1_data.json` 取值（主agent已用 `slice_chapter_data.py` 从 base_vars / extracted_data 切片并选定，每字段带 status 与溯源）。status=OK 直接用；EMPTY/MISSING 在 Word 中统一写 `【待填写】`、详细字段名记入 todo；CONFLICT 取 candidates[0] 并在回复中报告冲突。
> ⛔ **禁止打开 `extracted_data.json`、禁止 jq/grep/python 探测任何 JSON 字段路径**——它的 `sub_projects` 是提取中间态（同一子项目几十份同名冲突副本 + 兄弟项目混入），jq `[0]` 必命中空壳，探路即死循环（历史事故）。你要的字段全在切片里，切片没有的就是没有。

## 本章形态与总原则

⛔ **本章无论何时都要写，不存在"跳过"的情况。表格已填 ≠ 本章已完成。**

典型形态就是「**表格已由业务填好、正文一个字没有**」（实测某底稿：项目概况表 34/34 全填满，三节正文全空）。历史事故：agent 看表 1 有数就判定第一章已完成、整章跳过，交付时（一）（三）两节只剩小节标题 + 表标题 + 表下注。第三步的 `第一章分节[（一）/（二）/（三）]` 检查会**剔除标题、表标题（「表N …」）、表下注（「注N：…」）后逐节数实质正文**，光有表蒙不过去。

- **已填的不动**，并当作数据源——你写的一切必须与它一致，不一致就是错
- **空着的必须尽量填**，能写多少写多少。⛔ 不许因为"这里是空的"就跳过
- 只有确实取不到的**单个字段**才写 `【待填写】`，**不得整节留空**
- 本章段落在模版里**没有可替换的指导文字锚点**（业务已删干净）→ **每个小节写 1 个 `paragraphs` 条目**：`match` = 小节标题原文，`replace` 首段 = 标题原文本身、其后用 `\n` 接正文段，`styles` 首位写 `"Heading 2"`、正文段写 `null`（命中标题样式段落必须声明 styles，否则预检 ERROR；声明了即放行，这是 ch1 的合法例外，提示词模板已同步）。预检若报「match 多处命中」，加 `occurrence` 指定第几处。

  ⛔ **不要用 `insert_paragraphs` 写正文**——它是表下注专用：条目带 `citations` 时文字会被渲染成「注：本表数据提取自……」话术拼在正文后，而本章（一）（三）强制带括注；且它的 `text` 不拆 `\n`、多条目同锚点会逆序插入。

  条目格式示例（照这个写，不要自创字段）：

  ```json
  {"match": "（一）项目概况", "section": "（一）",
   "replace": "（一）项目概况\n本项目为所有权类基础设施项目，标的资产为……\n【子项目名称】位于……，于……开始运营，申报基准日评估净值为……万元。",
   "styles": ["Heading 2", null, null],
   "citations": [{"type": "material", "attachment_no": "25-1",
                  "doc_name": "资产评估报告", "page": 43, "anchor": "评估净值为"}]}
  ```

## （一）项目概况

锚点 `（一）项目概况`。**表格已填则绝对不要动**；未填则连表一起填。

说明【本项目】的【项目类型】，标的资产为【基础设施项目】。注意如果有不止一个项目，则请分别予以说明。

说明【子项目名称】的【资产范围】，【建设规模】，【用地面积】，【建筑面积】，【计费机柜】总数，【机柜总功率】，于【运营起始时间】开始运营，项目在【申报基准日】的资产评估值为【不动产评估净值】。注意如果有不止一个项目，则请分别予以说明。

**四个复合行的拼法**（业务定的口径，照此拼）：

- 建设内容和规模 → 5 项用中文逗号「，」按序连接：土地面积 → 计费机柜 → 机柜总功率 → 建设规模合计 → 底层资产
- 开竣工时间 → 【开工时间】**和**【竣工时间】，各精确到年月（只有竣工年份不合格）
- 决算总投资（万元）→ 直接取【建设规模合计】（业务认定与「项目建设规模合计」同源）
- 项目权属起止时间及剩余年限 → 3 项用顿号「、」连接；剩余年限 = 权属到期日 − 申报基准日，**强制计算**

**评估值 vs 评估净值**：`评估净值 = 评估值 − 基础设施基金对外借入款项中拟用于收购的部分`。材料**未提对外借款时两者相等**，此时两行填同一个数；提到借款则必须分别取值，不可一律填净值。「项目建设规模合计」填**金额**，不是面积或机柜数。

## （二）特殊限定情况说明

锚点 `（二）特殊限定情况说明`。看下该项目的【行业领域】：

1.对于燃煤发电项目，应说明项目具备以下一项或多项条件的具体情况：纯凝工况最小发电出力在30%额定负荷及以下；掺烧生物质、氢、氨等低碳燃料，掺烧热量比例不低于10%；配备大规模碳捕集利用与封存（CCUS）设备。

2.对于园区基础设施项目，如项目底层资产中包括酒店、配套底商，应详细说明酒店、配套底商的权属情况；与底层资产中的园区基础设施部分资产的物理关联关系，如是否为同一栋建筑；纳入底层资产的酒店、配套底商合计占同一单体建筑的面积比例。

3.对于文化旅游基础设施项目，如项目底层资产中包括配套旅游酒店，应详细说明旅游酒店的权属情况，地理位置情况，是否在景区规划范围内。

4.对于消费基础设施项目，如项目底层资产中包括酒店、商业办公用房，应详细说明酒店、商业办公用房的权属情况；与底层资产中的消费基础设施部分资产的物理关联关系，如是否为同一栋建筑；说明底层资产中酒店、商业办公用房的建筑面积占底层资产总建筑面积的比例。

如果【行业领域】不涉及上述 4 个类型，则**直接输出「不涉及。」，不要输出其他文字**：不解释原因，不复述模板的4类情形，不增加附属事项。如涉及，则按该类要求逐项写实质内容；数据取不到时原位写 `【待填写】`，不得编造。

⚠️ **数据中心类属"新型基础设施"，不在这 4 类内 → 写「不涉及。」**

## （三）可扩募资产情况

锚点 `（三）可扩募资产情况`。**正文与表格都要写**。

描述【发起人简称】的主要业务、已开展业务的城市，目前正在推动的业务和扩展的城市，字数控制在 200 字以内。截至【申报基准日】，【发起人简称】可扩募资产包括哪些。

分支判断（看**摘要表**「首次发行项目／新购入项目」）：

- **首次发行项目** → 开头只写“本项目为首次发行项目。”，然后直接写发起人业务布局和可扩募资产。不解释“不是扩募”，不展开扩募豁免/无扩募分支。
- **已发行 REITs 的新购入（扩募）项目可不提供** → 写「本项目为已发行基础设施 REITs 新购入项目，根据相关要求可不提供可扩募资产情况。」
- 确实缺乏可扩募资产（行业共性原因），或首发规模超 50 亿需放宽要求 → 详说缺乏原因与企业可扩募资产实际情况

## 每个小节末尾都要加括注写清来源（本章硬要求）

第一章只有几段，靠全局 50% 的来源标注覆盖率兜不住——几段全无括注也不影响全局比例。所以本章**逐节**校验（第三步 `第一章来源[（一）/（三）]`，缺一节即 FAIL）：

| 小节 | 括注要求 |
| --- | --- |
| （一）项目概况 | **必须有**。正文两段末尾各加一处，写清项目类型/资产范围/建设规模/评估净值的来源 |
| （二）特殊限定情况说明 | 写「不涉及。」时**免括注**（它是判定结论不是数据，强制加只会逼出编造的来源）；写实质内容时要加 |
| （三）可扩募资产情况 | **必须有**。发起人业务与城市布局、各资产的规模/持股比例都要有来源 |

话术只用 `citation_rules.json` 里的四类，不要自创：

- 取自输入数据 → `（提取自附件25-1《资产评估报告》第43页）`
- 沿用初稿已填值（表1／摘要表）→ `（沿用初稿摘要表）` / `（沿用初稿表1）`
- 自己算的（如剩余年限）→ `（据不动产权证到期日与申报基准日计算）`
- 确实取不到 → Word 只写 `【待填写】`，字段路径写入 todo

⚠️ **数据来自初稿或摘要表也要标**，不能以"这数是业务填的、不用标"为由省略——第三步按段落检测，不认这个理由。
⚠️ 括注**不计入篇幅门槛**（字数统计前自动剔除），不能拿括注凑字数。

## 表格怎么交给脚本

⛔ **不要写 `table_index` / `row` / `col`**。把上面两张表按实际数据填好，原样输出到 `<work_dir>/ch1_tables.md`（保留「表#  标题」这一行），主agent跑 `md_table_to_fill_plan.py` 去实际文档实测算坐标。**表号统一写 `表#`，不要自己编数字。已填好不用动的表，不要出现在这个文件里。**
