# 第0章「摘要表 / 释义」写作指南

> 手工维护，脚本不覆盖。配套 `chapter_examples/ch0_example.md`（标准范例）。
> **本章真实结构请现读，不要用预生成切片**（切片的 table_index 是官方模版序号，遇初稿会整体偏移）：
> ```bash
> python scripts/read_chapter.py "<填充基底.docx>" "（前置：封面/摘要表/释义）" "一、项目基本情况"
> ```
> 它输出段落原文（取 `match` 用）、每张表的**实际 table_index / 尺寸 / 全部行**，并直接带出已填内容——不必再单独读一遍 docx 判断哪些已填。


## 核心定位：有底稿时，摘要表是**全文最权威的数据源**

摘要表**通常由业务人工填写并已核对过**（实测某底稿 43/44 单元格已填、释义表 164/165 已填）。所以：

- ⛔ **有底稿且已填 → 一个字都不要动**。不重新生成、不覆写、不"优化措辞"
- ✅ **它是全文口径的唯一基准**：其余各章凡涉及同一数据（项目名称、评估值、主体名称、募集规模），**必须与摘要表逐字一致**；不一致就是错，且**以摘要表为准**
- 与证明材料冲突时**不擅自改摘要表**，记入第三步核查报告交业务判断
- **未填时才需要填**（走 phase 0 蓝图脚本），能填多少填多少，取不到的单格标【注：……待核实】，不得整表留空

## 摘要表 22 个字段：13 个是主体/中介机构，直接就是 `base_vars`

**有底稿时，`base_vars.json` 应当直接从摘要表读取**——它们已经业务核对，比从 `extracted_data.json` 提取更可靠。

## 释义表

- 已填 → **原样保留，不动**（术语定义一改就会与全文不一致）
- 未填 → 按材料中实际出现的主体与术语逐条补，能写多少写多少；个别取不到定义的条目标【注：待业务确认】，**不要整表留空**
- 校验器对释义表只报 INFO、不阻断交付

释义表典型条目（参考 `ch0_example.md`）：本项目/本基金简称、原始权益人及其简称、上市公司、专项计划、项目公司、各子项目、基金管理人/资产支持证券管理人、各中介机构、申报基准日，以及行业术语（PUE、上架率、计费机柜、NOI、IDC 等）。

## 表头处理（仅在需要自己填时）

- 摘要表的「资产所在地」「资产范围」**去掉括号提示语**（「（明确到县区级）」「（线性工程填写起止地点…）」）
- **表1 中相同字段的提示语要保留**（仅把逗号改为分号）——两张表处理方式不同，别搞反
