> 手工维护，脚本不覆盖。配套 `chapter_examples/ch5_example.md`（标准范例·万国，80段/7表）。锚点数据在 `chapter_examples/manifest.json` 的 ch5 条目（`anchor_map` / `anchor_styles` / `$ambiguous_matches` / `$forbidden_anchors`）。

**表15~表22 已由主agent用 `gen_phase_fill_plan.py` 基于 phase5 蓝图生成**（表15/16/22 走 `rebuild_tables` 整表重建，随 phase5 主批次一次应用），**不需要你做、也不要你跑该脚本**。你**只写正文段落**，`tables` 留空数组。**正文引用表格一律写「下表」「如下表所示」，⛔ 禁止硬编码「表19」这类表号**（编号交付前由 renumber_tables.py 全篇重排，硬编码必然指错；模版标题里自带的「（填写表19）」是待清理残留，见下方第 2 节）。
> **本章真实结构读 `<work_dir>/ch5_structure.txt`**（主agent委派前已用 read_chapter.py 从实际填充基底现读并核过章界——预生成切片的 table_index 是官方模版序号，遇初稿会整体偏移）。⛔ 子agent不自己跑脚本、不读基底 docx。主agent切结构命令：
> ```bash
> python scripts/read_chapter.py "<填充基底.docx>" "五、项目合规情况" "六、运营管理安排" > <work_dir>/ch5_structure.txt

> 它输出段落原文（取 `match` 用）、每张表的**实际 table_index / 尺寸 / 全部行**，并直接带出已填内容——不必再单独读一遍 docx 判断哪些已填。

> ⚠️ **字段路径以实际数据为准**：本指南写的 `compliance.procedures_not_applicable` / `procedures_missing` / `transferability.restrictions` / `macro_policies.conformity_metrics` / `foreign_investment_access` 是新版 schema 路径。老版 extracted_data 里同类内容在 `not_applicable_items` / `encumbrances` / `land_use_policies` / `telecom_licenses` / `investment_procedures` 等键下。**动笔前先 `print(sorted(compliance.keys()))` 看实际键名，按语义对号取数**；路径取不到≠数据缺失，不得据此写占位符或整节「不涉及」。


## 本章最大的历史事故：不是写太少，而是写对了内容放进错误的小节

70 个条目挤 30 个锚点 → 宏观政策段落落到（二）投资管理手续说明段。下面 8 条硬要求，**第 1、2 条最容易出事，先读**。

### 1. 锚点纪律：`paragraphs` 条目数必须 ≤31

现读本章会看到 60 段，但其中 30 段是**小节标题 / 表格标题 / 表下注**——它们不是指导文字、不需要替换、**更不能当 match**；真正可替换的指导文字只有 30 段（+1 条标题清理）。而范例正文有 80 段——**不要按「一段输出＝一个条目」建模**，那样必然编造 match 并把内容写进错误小节。

- **match 只能逐字复制 `manifest.json` 里本章 `anchor_map` 的字符串之一**，不要自己从切片里另选子串、不要凭记忆写、不要改标点。一个锚点最多一个条目
- **一个小节要写的全部段落（含该节内的编号小标题）用 `\n` 拼进该锚点条目的同一个 `replace`**，**主agent应用时** `fill_docx.py` 会把 `\n` 拆成独立段落并继承原段格式（**该脚本由主agent执行，你不要跑**）。例如（一）宏观政策要写 20+ 段，就全部写进「说明项目是否存在违背相关国家重大战略」这一个条目的 `replace` 里
- **fill_plan 顶层必须写 `"chapter": "五"`；每个 `paragraphs` 条目必须写 `"section"`**，取值为 `anchor_map` 的键（如 `"（三）3"`）。预检会校验该条目命中的段落是否真落在这个小节区间内，落错节直接报 ERROR 拦下——**这是防错位的最后一道闸门，不要省略**
- 已知歧义陷阱（详见 `manifest.json` 的 `$ambiguous_matches`）：`1.总体情况` 在（三）1 和（四）1 **重复出现两次**，绝不可当 match；（三）3 的（1）划拨与（2）协议出让两段**尾部完全相同**，match 必须含开头的「（1）以划拨方式」/「（2）以协议出让方式」；`说明发起人（原始权益人）` 这 12 字**同时命中 4 段**。**多命中且没写 `occurrence` 的 match 会被预检按 ERROR 拦截**

### 2. 标题层级与样式：7 个 H3 模版里没有，必须由你的 `replace` 新建

```
[H1] 五、项目合规情况
  [H2] （一）符合宏观管理政策要求情况        ← 模版下面 0 个 H3，需新建 5 个
    [H3] 1.国家重大战略与总体规划
    [H3] 2.专项规划和区域规划
    [H3] 3.《产业结构调整指导目录》和行业政策
    [H3] 4.外资准入
    [H3] 5.其他专项政策
  [H2] （二）投资管理手续合规情况            ← 模版已有 5 个 H3，不要动
    [H3] 1.各类项目均应取得的投资管理合规手续 / 2.特定行业投资管理合规手续
    [H3] 3.相关手续不涉及的情况 / 4.相关手续缺失的情况 / 5.连廊、夹层等建筑情况
  [H2] （三）土地使用合规情况                ← 模版已有 3 个 H3，其中 2 需清理标题
    [H3] 1.总体情况
    [H3] 2.土地使用手续办理情况              ← 模版是「…（填写表19）」，须去掉后缀
    [H3] 3.具体情况说明
  [H2] （四）可转让性有关情况                ← 模版已有 3 个 H3，不要动
    [H3] 1.总体情况 / 2.具体情况 / 3.承诺函出具情况
  [H2] （五）政府和社会资本合作（PPP）项目合规情况   ← 无 H3
  [H2] （六）税收处理情况                    ← 模版下面 0 个 H3，需新建 2 个
    [H3] 1.承诺函出具情况
    [H3] 2.项目涉税情况
```

**为什么必须显式声明样式**：段落替换保留原段落的 Word 样式，`\n` 拆出的每个新段落也继承同一样式。所以①模版没有的 H3 不会自己出现；②如果 match 命中的是标题段落而你没声明样式，替换出的正文会**全部带标题样式**（大号加粗、层级混乱，还把正文塞进导航窗格和自动目录）。

- **`styles`（数组）**：与 `replace` 按 `\n` 拆出的**非空分段一一对应**，需成为小标题的分段写 `"Heading 3"`，正文分段写 `null`
- **`style`（字符串）**：本条**所有**分段统一套一个样式，只用于「只改标题文字、保持标题样式」
- 哪个锚点该怎么写见 `manifest.json` 的 `anchor_styles`

示例（（六）新建 H3 + 正文）：

```json
{"match": "说明发起人（原始权益人）对项目依法依规缴纳税收",
 "section": "（六）",
 "styles": ["Heading 3", null, null],
 "replace": "1.承诺函出具情况\n2024年12月31日，原始权益人……出具《……关于税收处理的承诺函》，承诺：“……”。\n相关情况详见附件21-1。"}
```

示例（（三）2 标题清理，**全章唯一允许拿标题当 match 的条目**）：

```json
{"match": "2.土地使用手续办理情况（填写表19）",
 "section": "（三）2",
 "style": "Heading 3",
 "replace": "2.土地使用手续办理情况"}
```

⚠️ 这一条**必须写**：「（填写表」是交付校验的 FAIL 关键词，而它藏在这个 Heading 3 标题里，不清理就过不了第三步。

### 3. （一）宏观政策必须写成 5 个编号小节

1.国家重大战略与总体规划 / 2.专项规划和区域规划 / 3.《产业结构调整指导目录》和行业政策 / 4.外资准入 / 5.其他专项政策（数据中心类通常为绿电政策）。

每小节 = 逐份政策段（一份政策一段，格式「YYYY年M月，{发布机关}发布《{名称}》，{政策要点含目标数值}」）+ 1 个符合性论证段。

- 政策原文取 `industry_knowledge.json` 的 `<行业>.macro_policies.<小节键>`
- 段落骨架取 `text_templates.json` 的 `paragraph_templates.macro_policy_<行业>`
- 项目端对标数据取 `extracted_data.json` 的 `compliance.macro_policies.conformity_metrics`（上电率／PUE／绿证／园区资质）

**本节整体不少于 20 段 / 3,000 字**（标准答案 25段/3,700字），不得压缩成一段话。⚠️ 本节只有 2 个锚点，这 20+ 段必须用 `\n` 分配到这 2 个条目里（建议：政策清单段放「列出项目所涉及的国家重大战略、宏观调控政策」，5 个编号小节全文放「说明项目是否存在违背相关国家重大战略」，并用 `styles` 给这 5 个小标题分段标 `"Heading 3"`）。

### 4. （一）4.外资准入

读 `compliance.foreign_investment_access`。`applicable=false` 时一句话说明无外资股东即可；为 true（境外上市主体／VIE 架构）时必须写：适用法规限制条款 → VIE 是否构成外商投资的论证（引商务部问答、工信部〔2015〕196号通告、公开案例）→ 发行后架构（许可证由项目公司直接持有、股东为专项计划管理人、不再涉及VIE）→ 结论及交叉引用位置。

### 5. （二）3.不涉及情况 / 4.缺失情况

逐条对应 `compliance.procedures_not_applicable` 与 `compliance.procedures_missing` 成小节。必须引用**法规名称+文号+条款原文**（150字以上）与**有权部门函复原文**（200字以上）。

缺失情况须按三类情形分别成节：建设时无需办理但现行应办理／建设时应办理但现行已取消或合并／新旧均需办理。无对应事项的写「不涉及」，**不得整节省略**。

⚠️（二）3 只有 1 个锚点、（二）4 有 3 个锚点（对应三类情形各一个），逐条小节用 `\n` 装进去。

### 6. （三）3.土地分情形说明 与（四）2.转让限制具体情况

按项目实际土地取得方式（划拨／协议出让／招拍挂或二级市场／经营收益权类／项目公司不拥有土地使用权／集体土地）**只写命中的情形**——（三）3 的 6 个锚点与这 6 类情形一一对应，**不命中的情形在其锚点条目里写「本项目不涉及。」，不要把内容写到别的情形的锚点上**。

转让限制按 `compliance.transferability.restrictions` 的每个 `type` 成一个小节（产业用地监管规定、出让合同约定、抵押担保／融资租赁质押、行业许可、园区优先购买权等），每节写清依据文件+条款原文+限定对象+解除方式+解除函原文+附件编号，全部装进（四）2 的锚点条目。

⚠️ `ch5_example.md`（万国）是「招拍挂（挂牌）出让+境外VIE架构+境外股东涉税」情形。**若本项目是协议出让、划拨或纯境内架构，按本项目 extracted_data 写，不要照搬范例的情形分类、外资准入论证与涉税主体。**

### 7. 来源标注分两类，不要混

- **`knowledge` 类**：法规／政策／产业目录的**条款原文引用**（`name`=法规全称、`doc_number`=文号、`clause`=条款号，取自 `procedures_not_applicable.legal_basis` / `procedures_missing.rule_then` / `rule_now` 或 `industry_knowledge.json`）
- **`material` 类**：部门函复原文、承诺函、无异议函、权证、手续文件（`attachment_no` 取记录自带的字段）

（一）宏观政策各段几乎全是 `knowledge`，（二）(三)(四) 的事实叙述几乎全是 `material`。表15~表22 的来源已由脚本写入备注列／表下注，**你不要再为表格写 citations**。由于一个条目承载整节内容，`citations` 数组会较长——用 `anchor` 把每条来源定位到 `replace` 里对应的数据子串。**小标题分段不要标来源。**

### 8. 篇幅：≥70 段 / ≥6,500 净字

标准答案实测：润泽 109段、万国 80段（现范例即万国）。注意统计的是**最终文档的段数**，即所有 `replace` 中 `\n` 拆分后的段落总数，**不是 `paragraphs` 条目数**——31 个条目写出 70+ 段是正常且正确的形态。
